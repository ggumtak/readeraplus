# 이북 AI 사전

선택 → 검색 → AI에서 이북리더기는 **앱에 포함된 Claude 사전 화면**을, 일반 폰은 기존 ChatGPT를 사용한다. 둘 다 선택한 글에 ` 뜻`을 붙인다. 기기 판별이 아직 없으면 AI 탭에서 비동기로 확인한다.

기본 시스템 지침은 일반 대화용이다. 사전 역할·독서 한정·기본 2~6문장 제한을 두지 않으며, 일상 질문에도 사용할 수 있다. 본문 선택 시 ` 뜻`을 붙이는 것은 질문 자동 입력 기능이다. 사용자 지침과 선택한 답변 길이는 다음 요청에 별도로 적용한다.

ChatGPT 로그인이나 사이트 서버가 필요 없다. 기존 `chatgpt.site`와 `extras.einkAiSite` 설정은 사용하지 않는다.

## 사용

1. 이북에서 본문을 선택하고 검색 → AI 탭을 연다.
2. 처음에 표시되는 Claude API 연결 창에 Anthropic API 키를 한 번 입력한다. `이 기기에 키 저장`을 켜면 이 앱의 WebView localStorage에 보관한다. 끄면 현재 창에서만 사용한다.
3. 기본값은 **Haiku 5.5 / 높음**. 입력창의 모델 버튼에서 Haiku 5.5·Sonnet 5.5·Opus 5.5, 낮음·중간·높음·엑스트라를 선택한다. 이전 버전의 기본값(Haiku / 낮음, Haiku / 중간, Sonnet / 중간)과 비어 있는 사용자 지침은 한 번만 새 기본값으로 옮기고(설정 버전 4), 이후 사용자가 선택한 모델과 지침은 유지한다. 기본 사용자 지침은 무협·선협 소설의 한자어를 글자별 훈·음과 뜻, 소설 속 쓰임으로 풀고, 확실하지 않은 한자 표기는 추측이라고 밝히게 한다.
4. 입력창 왼쪽 위 **돋보기**를 누르면 웹 검색을 켜거나 끈다. **진한 배경에 흰 돋보기는 켜짐**, **흰 배경에 테두리만 있으면 꺼짐**이다. 켜두면 Claude가 질문에 따라 필요할 때만 검색하고, 일반 뜻풀이는 검색 없이 바로 답하도록 안내한다. 끄면 검색 도구를 요청에 포함하지 않는다. 선택은 다음에 열어도 유지한다. 켜져 있어도 매번 검색하는 것은 아니며, “검색해서 알려줘”라고 직접 요청할 수 있다.
5. 검색한 답변은 본문에 출처 번호와 아래 출처 링크를 표시한다. 출처를 직접 누를 때만 외부 브라우저를 연다. 검색 중에는 정적인 안내를 표시하고 답변 중지 버튼으로 취소할 수 있다.
6. 햄버거 메뉴에서 최근 대화를 열거나 **새 세션**을 추가한다. 최근 20개 세션, 세션별 최근 30문답(표시 텍스트 30,000자, 직렬화 90,000자 한도)을 이 기기에 저장한다. 질문 시작·답변 완료·세션 이동·창 종료 때만 저장하며, 스트리밍 토큰마다 저장하지 않는다. 메뉴는 제목 목록만 읽고 선택한 세션의 내용만 불러온다. 창을 다시 열어도 저장된 질문을 자동 재전송하지 않는다. 책에서 새로 선택한 질문은 새 세션에서 보낸다.
7. 입력창 왼쪽의 **사진 버튼**으로 사진 1장을 질문에 붙인다. 앱이 고른 사진을 긴 변 1568px JPEG로 줄여 페이지에 넘기며(WebView의 파일·콘텐츠 접근은 계속 꺼 둔다), 질문 없이 보내면 "이 사진을 설명해 주세요."로 묻는다. 사진은 현재 창의 후속 질문에도 함께 보내지만 대화 기록에는 저장하지 않는다(기록에는 `[사진]` 표시만 남는다). 선택 팝업 ⋮의 **스크린샷**은 현재 화면을 사진 › ReaderaPlus에 저장하므로 그 사진을 바로 붙일 수 있다.
8. 메뉴 **왼쪽 아래 톱니바퀴**에서 사용자 지침(최대 4,000자), 답변 길이, 글자 크기(18/20/22px), 모델·노력 수준, 웹 검색, 대화 저장과 API 연결을 설정한다. 지침은 모든 세션의 다음 API 요청부터 전달한다. 저장을 끄면 기존 최근 항목은 유지하고 새 대화는 현재 창에서만 유지한다. 대화의 개별·전체 삭제는 확인 후 실행하며 키와 설정은 유지한다.
9. 메뉴 → 톱니바퀴 → Claude API 연결 관리 → 연결 해제로 저장된 키를 삭제할 수 있다. 앱 데이터 삭제·앱 제거 시에도 키가 사라진다.

키를 저장하는 localStorage는 암호화된 금고가 아니다. 개인 기기에서만 사용하고, 다른 사이트에 키를 넣지 않는다. 외부 브라우저와 앱의 키 저장 공간은 별개다.

## 성능과 보안

- `app/src/main/assets/ai-dictionary.html` 약 59KB (gzip 약 18KB) 한 파일에 HTML·CSS·JavaScript를 모두 넣었다. 화면을 여는 HTTP 요청은 없다. 인터넷은 Claude 답변을 요청하거나 사용자가 출처를 열 때만 필요하다.
- 외부 폰트·SDK·프레임워크·음성·애니메이션·로그인 코드가 없다. 스트리밍 첫 글은 즉시, 이후 화면 갱신은 500ms 단위로 묶고 최종 결과를 즉시 표시한다.
- WebView는 앱의 HTML을 고정 HTTPS origin에서 제공한다. 이 주소는 앱 내 전용이며 일반 브라우저에 넣는 사이트 주소가 아니다.
- API는 `https://api.anthropic.com/v1/messages`에 브라우저 직접 호출 헤더를 붙여 전송한다. 중간 프록시 서버가 없다. 키는 요청 헤더에만 있고 질문·URL·소스에는 넣지 않는다.
- CSP는 외부 스크립트·프레임·폼 제출을 차단하며, 네트워크 요청은 Claude API로 제한한다. WebView 자체도 다른 URL의 요청과 페이지 이동을 막는다. 출처 링크는 사용자 터치가 있는 메인 프레임의 HTTP(S) GET만 외부 브라우저로 전달하고, 계정 정보가 든 URL·앱 origin·API endpoint·다른 scheme은 거부한다. JavaScript 네이티브 브리지는 사용하지 않는다.
- WebView 데이터는 Android 클라우드 백업과 기기 이전에서 제외한다. 앱 자체의 설정 백업에도 키를 넣지 않는다.
- 이북에서 다른 사전을 보는 동안 AI를 미리 보내지 않는다. 대화는 짧게 제한하며 창이 닫히면 진행 중 응답을 중지하고 부분 답변을 저장한다. 별도 대화 저장 서버를 두지 않는다.
- 모델 ID는 `claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-opus-5-5`, 엑스트라는 `xhigh`다. 직접 호출이 API 계정 정책이나 오래된 WebView에서 막히면 연결 오류가 표시된다.
- 검색은 Anthropic 서버의 `web_search_20250305`와 `tool_choice: auto`로 실행한다. 이북에서 검색 사이트의 JavaScript를 실행하지 않는다. 각 API 요청의 검색은 최대 3회, `pause_turn` 자동 이어받기는 최대 2회다. 검색 결과의 암호화된 내용·출처·thinking 서명은 저장 한도 안에서 보관하고 같은 모델의 후속 요청에 그대로 전달한다. 다른 모델로 바꾸거나 저장 용량을 넘으면 표시된 답변과 출처를 남기고 해당 암호화 문맥을 생략한다. 대화의 표시 텍스트는 약 17,000자, 전체 검색 문맥은 약 260KB로 제한한다.
- 웹 검색은 실제 검색 1회당 $0.01와 토큰 비용이 추가된다. API 계정에서 검색을 껐거나 검색 자체가 실패하면 별도 안내를 표시한다. 실제 검색에는 네트워크 대기 시간이 추가된다.

API 형식·검색 요금: [Anthropic 웹 검색 문서](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool), [서버 도구와 pause_turn](https://platform.claude.com/docs/en/agents-and-tools/tool-use/server-tools).

같은 HTML은 별도 HTTPS 정적 호스팅에도 사용할 수 있다. GitHub Pages를 쓰더라도 계정 로그인이나 API 키를 저장하는 서버는 필요 없다. 앱 안에서는 호스팅 없이 즉시 열리는 쪽이 기본이다.

## 검증

`node --test tools/ai-dictionary/test.mjs` 35개는 API 요청·스트림·취소·키 저장·초기 화면·CSP·크기 제한·검색 on/off·출처·암호화 검색 문맥·pause_turn·설정 이전, 세션 분리·복원·지연 읽기·용량 제한, 사용자 지침·글자 크기, 사진 첨부·검증, 저장 실패, 취소·삭제를 확인한다. Android URL 제한과 이북/폰 분기는 Gradle 단위 테스트로 확인한다. 실제 키를 사용한 응답과 e-ink 화면 반응은 실기기에서 확인한다.

HTML의 스크립트를 바꾸면 CSP의 `sha256-` 값도 해당 `<script>` 본문 해시로 갱신해야 한다. 테스트가 해시 불일치를 검출한다.
