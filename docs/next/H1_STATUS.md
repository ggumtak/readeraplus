# 빠른 빌드: 1차 리뷰 + H1 (2026-10-02)

## 변경
- `wave1_review_resolution.md`에 지적 22건 각각의 판단과 근거를 기록했다.
- ReaderActivity가 마지막으로 화면에 보여 준 책과 anchor를 instance state에 저장한다.
  재생성은 원래 VIEW URI나 처음 실행했던 책이 아니라 저장한 책 id로 열린다.
- `reader_resume`에는 첫 페이지를 표시한 뒤 책 id만 기록한다. 사용자가 끝내면 해제하고,
  시스템 종료·업데이트 후 루트가 다시 열리면 기존 draw hold 경로로 책을 곧바로 연다.
- 복원 위치보다 최신 DB 위치(TTS) 또는 TXT 비율 재매핑이 우선한다.
- 파일 없음·휴지통 책은 복원하지 않으며 연속 자동 복원은 2회로 제한한다.
- 최근 앱으로 나갈 때 오는 UI_HIDDEN은 이미지 캐시를 지우지 않는다.
- 정보 화면에 최근 종료 사유를 IO에서 읽어 표시한다. 시작 경로에는 진단 작업이 없다.

## 검사
- `tools/typecheck.sh`: 성공, 오류 0건.
- `tools/unittest.sh`: 기존 1,045개 + 새 회귀 19개 = **1,064개 전부 통과**.
  Kotlin 2.1.0·Android API 35 android-all·JUnit 4.13.2로 실행했다.
- H1 회귀 테스트 17개: 잘못된 책, 재생성, 최신 TTS 위치, TXT 파싱 변경, 의도적인 닫기,
  직접 서재 이동, 재시도 제한, 기존 ‘앱 시작 시 읽던 책 열기’ 동작을 다룬다.
- PNG 비교 도구는 동일 이미지 PASS·본문이 다른 이미지 FAIL 확인.
- 검사 스크립트의 컴파일 실패 전파와 shell 문법 확인.
- GitHub Actions 70–78은 프로세스 종료, 강제 중지, history intent, 업데이트, 두 번째 책,
  ‘활동 보관 안 함’, 정상 닫기의 실제 화면을 비교한다. 에뮬레이터 결과는 아직 확인 전이다.

## 성능·후속
- 본문 측정·줄 나누기·페이지 넘김 경로는 바꾸지 않았다. 정상 책 열기는 nullable 복원 상태만 확인한다.
- 표식 쓰기는 첫 페이지 이후, 복원 유효성 확인과 재시도 기록은 서재의 기존 IO 경로다.
- 실제 Comet과 휴대폰의 첫 페이지·페이지 넘김 체감 및 최근 앱 복귀는 APK 설치 후 확인이 필요하다.
- H2·H3·H4와 Phase 0·W1은 이 빠른 빌드 뒤에 진행한다.
