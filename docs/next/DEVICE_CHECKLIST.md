# 코멧 실기기 점검표 (PLAN §5.4 성능 · §5.5 기기 점검)

CI에는 기기가 없어서 PLAN §5.4와 §5.5는 아직 실기기로 확인하지 못했다. 이 표대로 코멧 한 대와 휴대폰(삼성) 한 대로
혼자 끝낼 수 있다. 화면 문구는 a3b8826 기준으로 코드(`ui/`, `reader/`)와 대조했다(2026-10-04 문구 · 설정 정리: 넘김·화면
설정은 넘기기·터치·키 · 화면·밝기 · e-ink 새로고침(처음 이름 e-ink 화면) 세 페이지가 됐고, 돌아가기 표시는 "N쪽으로"다. 같은 날
리뷰 반영: 설정 첫 화면은 읽기 화면 · 조작·기능 · 서재 · 책 가져오기 · 기타 다섯 묶음, 묶음 머리글 18 sp와 묶음 위 2 px 검은 줄).

- **결과 칸 표기:** 통과는 ○, 실패는 ✕, 못 했으면 –. 숫자 항목은 값을 적는다. ✕이면 사진이나 그 앞뒤 로그 몇 줄을 남긴다.
- **항상 지켜야 할 네 가지:** 넘김 애니메이션 없음, 첫 페이지 전에 새 작업 없음, 동작 하나에 e-ink 갱신 한 번,
  무엇을 보이거나 숨기거나 설정을 바꿔도 읽던 위치 그대로. 어느 항목에서든 이 중 하나라도 어기면 ✕다.
- **순서:** §0부터 차례로 한다. 데이터를 지우는 항목(§15-2, 15-4, 15-9)은 맨 마지막에 한다.

## 0. 준비

1. APK는 GitHub `latest` 릴리스의 `ReaderaPlus-<번호>.apk`를 쓴다. 설치한 뒤 설정 › 정보에서 "버전 0.1.<번호>"를 적는다. 버전: ______
2. PC에서 `adb devices`로 기기가 보이는지 확인한다.
3. 로그를 켠다. 앱은 이 설정을 프로세스가 시작될 때 한 번만 읽으므로 **강제 종료까지 해야 한다.** 재부팅하면 다시 한다.
   릴리스 빌드에서도 나오며, `open … first page` 줄은 이 설정이 없어도 나온다.
   ```sh
   P=com.ggumtak.readeraplus
   adb shell setprop log.tag.RAPerf DEBUG
   adb shell setprop log.tag.RAThumbs DEBUG
   adb shell setprop log.tag.RANotes DEBUG
   adb shell am force-stop $P
   adb logcat -c
   adb logcat -v time -s RAPerf RAThumbs RANotes AutoBackup LibraryDb | tee comet_log.txt
   ```
4. 로그에서 읽을 줄:

   | 줄 | 뜻 |
   |---|---|
   | `open <책id>: first page N ms` | 책 열기를 시작해서 첫 페이지를 다 그릴 때까지 |
   | `turn N ms` | 넘김 입력부터 넘긴 페이지를 다 그릴 때까지. 스크롤 STEP의 한 화면도 이 줄로 나온다 |
   | `show OPEN\|TURN\|JUMP\|RELAYOUT s:<구간> o:<쪽 시작> a:<기준> g:<세대> Nms` | 페이지가 보일 때마다 한 줄. `RELAYOUT`은 쪽을 다시 나눴다는 뜻이다. **`s:`와 `o:`가 같으면 같은 글자로 시작하는 쪽이다** (위치 고정 확인에 쓴다) |
   | `afterOpen N ms` | 첫 페이지 다음에 메인 스레드에서 한 일 |
   | `count counted=N cached=M extra=E N ms` | 쪽수 계산. 새로 센 구간이 N, 캐시에서 읽은 구간이 M |
   | `grid p<첫 쪽>+<개수>: N ms (rounds …, hits H, rendered R)` (RAThumbs) | 썸네일 한 화면. R = 0이면 캐시에서(warm), R > 0이면 새로 그림(cold) |
   | `open: first rows N ms …`, `reload: N ms …`, `page <p>: N ms` (RANotes) | 독서 노트 첫 화면, 다시 읽기(검색 포함), 다음 쪽 |
   | `auto backup: <결과> in N ms` (AutoBackup) | 결과: `WROTE`, `UNCHANGED`, `NOT_DUE`, `BUSY` … |
   | `upgrade v2 → v3: N statements, M ms` (LibraryDb) | 업데이트한 뒤 첫 실행에서 DB 변환 |

5. 프레임과 메모리:
   ```sh
   adb shell dumpsys gfxinfo $P reset                                    # 여기서부터 센다
   adb shell dumpsys gfxinfo $P | grep -E "Total frames|Janky|percentile"
   adb shell dumpsys meminfo $P | grep -i "TOTAL PSS"
   ```
6. 시험할 책: 큰 TXT(PLAN 기준 14.8 MB, 미리 한 번 열어 색인을 만들어 둔다), "1화"처럼 회차가 있는 웹소설 TXT, 그림이 많은 EPUB, 색이
   다른 인용문 5개가 한 쪽에 있는 책.
7. **"갱신 한 번"은 눈으로 본다.** 화면이 한 번에 바뀌면 ○다. 두 번 깜빡이거나 글자가 잠깐 다른 자리에 보였다가 돌아오면 ✕다.
8. 읽기 화면 조작:
   - 가운데를 탭하면 메뉴가 열린다.
   - 위 막대: 뒤로, 북마크, 듣기, 검색, 목차, 읽기 설정(톱니), ⋮. 그 아래에 밝기 막대와 "밝기 옵션"(▾)이 있다.
   - 아래 막대: 쪽 번호(누르면 페이지 이동), 화면 회전 잠금, 고정(핀), 페이지 위치 막대, 이전 챕터 / 다음 챕터.
   - 읽기 설정(톱니) 퀵옵션: 맨 위 "전체 읽기 설정 ›"과 닫기, 그 아래 글자 크기, 굵기, 줄 간격, 문단 간격, 좌우 여백, 상하 여백,
     글꼴(2026-10-04). 나머지는 "전체 읽기 설정"(= 설정 › 읽기 설정)과 설정의 넘기기·터치·키 · 화면·밝기 · e-ink 새로고침에
     있다. ⋮ › 설정으로 연 설정에는 서재 · 책 가져오기 묶음과 읽기 기록 · 백업·복원 · 캐시 비우기가 없다(서재 ⋮ › 설정에는
     있다). 설정에서 바꾼 값은
     책으로 돌아올 때 한 번에 적용된다.

## 1. 업데이트하기 전에 기준값 재기 (코멧에 R3 이전 빌드가 있을 때만)

R2 기준값은 문서에 남아 있지 않다. 지금 코멧에 깔린 빌드가 R3 이전이면 업데이트하기 전에 먼저 잰다. 이미 R3이면 1-1~1-3은
건너뛴다. 그 경우 §2의 "기준 + N" 항목은 값만 적어 두고, 판정은 다음 빌드와 비교해서 한다.

| # | 할 일 | 합격 조건 / 적을 값 | 결과 |
|---|---|---|---|
| 1-1 | 큰 TXT를 서재에서 열고 뒤로 나가기를 5번 | `open … first page` 중앙값 | ___ ms |
| 1-2 | 같은 책에서 다음 쪽으로 10번 넘기기 | `turn` 중앙값 | ___ ms |
| 1-3 | 책을 뒤로 닫은 뒤 `adb shell am force-stop $P; adb shell am start -W -n $P/.ui.library.LibraryActivity`를 6번 | 첫 번째를 뺀 TotalTime 중앙값 | ___ ms |
| 1-4 | 새 APK를 덮어 설치(`adb install -r ReaderaPlus-<번호>.apk`)하고 앱 실행 | `upgrade v2 → v3 … M ms`에서 M ≤ 50 | ___ ms |
| 1-5 | 업데이트한 뒤 첫 실행 | "이전 기록을 복원할까요?" 대화상자가 **뜨지 않는다** | |
| 1-6 | 책을 열고 톱니(퀵옵션), 그리고 톱니 › 전체 읽기 설정 › 여백·페이지 | 예전 기본 여백(18/16)이었다면 두 곳 모두 "좌우 여백 0", "상하 여백 0"으로 보인다 | |
| 1-7 | 한 쪽 넘기고 홈으로 나가서 5초 기다리기 | `auto backup: WROTE`. `adb shell ls /sdcard/Download/ReaderaPlus/backup`에 `readeraplus-auto-<8자>-<날짜>.json`이 생긴다 | |

## 2. 성능 기준 (PLAN §5.4, 코멧)

따로 적지 않으면 5번 재서 중앙값을 쓴다. "잡음 수준"은 같은 측정을 5번 했을 때 나온 최대값과 최소값의 차이 안이라는 뜻이다.

| # | 항목 | 하는 법 | 합격 | 결과 |
|---|---|---|---|---|
| 2-1 | 책 열기 (큰 TXT, 캐시 있음) | 1-1과 같다 | ≤ 1-1 + 10 ms | |
| 2-2 | 노트에서 열기 | 리더를 닫은 상태에서 서재 서랍 › 독서 노트를 열고, 큰 TXT의 인용문을 탭한 뒤 뒤로 나온다. 5번 | 2-1과 잡음 수준 차이 | |
| 2-3 | 페이지 넘김 | 다음 쪽 10번씩: (a) 기본 설정, (b) 색이 다른 인용문 5개가 있는 쪽, (c) 위 슬롯 + 아래 슬롯 3개 + 진행 막대 | 셋 다 1-2와 잡음 수준 차이 | a__ b__ c__ |
| 2-4 | afterOpen | 책을 열 때마다 | `afterOpen` ≤ 4 ms | |
| 2-5 | 열자마자 넘기기 | 첫 페이지가 보이고 1초 안에 다음 쪽 | 그 `turn`이 2-3(a)와 잡음 수준 차이 | |
| 2-6 | 설정 변경으로 다시 나누기 | 큰 TXT에서 톱니(퀵옵션) › 글자 크기 +를 빠르게 두 번(+1 sp) 누른다. 매번 −로 되돌리고 5번 | `show RELAYOUT … ms` ≤ R2 기준 + 5 ms. R2에는 이 줄이 없으므로 값만 적는다 | |
| 2-7 | 다시 나누지 않는 설정 | 설정 › 화면·밝기의 상태 표시 슬롯, 진행 막대, 상태 글자 크기, 인용문 색 표시, 그리고 전체 읽기 설정 › 스타일의 흑백 반전을 바꾸고 리더로 돌아온다 | 하나마다 `RELAYOUT` 줄 0개, 갱신 한 번 | |
| 2-8 | 최근 앱 복귀 (프로세스가 살아 있음) | 읽다가 홈 › 최근 앱 › 리더플러스 카드 | 새 `show` 줄 0개. 같은 쪽이 곧바로 보인다 | |
| 2-9 | 최근 앱 복귀 (프로세스 없음) | 책을 연 채 홈으로 가서 `adb shell am force-stop $P` 후 `adb shell am start -W -f 0x10100000 -a android.intent.action.MAIN -c android.intent.category.LAUNCHER -n $P/.ui.library.LibraryActivity` | 서재 화면이 한 번도 보이지 않고 같은 쪽이 열린다. TotalTime ≤ 1-3 + 1-1 + 50 ms | |
| 2-10 | 서재 콜드 스타트 | 1-3과 같다. 업데이트한 뒤 두 번째 실행부터 잰다 | ≤ 1-3 × 1.05 | |
| 2-11 | 쪽수 캐시 | 쪽수 계산이 끝난 책의 중간 쪽에서 글자 크기를 + 두 번 누르고, `count` 줄이 나올 때까지 기다린 뒤 뒤로 나갔다 다시 연다 | 다시 연 뒤 `count counted=0` | |
| 2-12 | 스크롤 STEP | ⋮ › 스크롤로 보기 › 다음 10번. 그다음 gfxinfo reset, 손가락을 대고 천천히 끌다가 놓은 뒤 gfxinfo | `turn` ≤ 2-3(a) + 2 ms. Total frames rendered는 1(놓을 때 한 번) | |
| 2-13 | 메모리 (스크롤 vs 페이지) | 같은 책에서 페이지 모드로 20쪽 넘긴 뒤 PSS, 스크롤 모드로 20화면 넘긴 뒤 PSS | 차이 ±1 MB | |
| 2-14 | 정지 상태 | 아래 슬롯에 시계를 켠다. gfxinfo reset 뒤 60초 동안 손대지 않고 gfxinfo | Total frames rendered 0 | |
| 2-15 | 미리보기 | ⋮ › 페이지 미리보기를 처음 열 때(cold), 닫았다 다시 열 때(warm) | cold ≤ 400 ms, warm ≤ 90 ms | |
| 2-16 | 독서 노트 | 목록 넘기기 "한 화면씩"으로 두고(서재 ⋮ › 설정 › 서재) 서재 서랍 › 독서 노트 열기, 다음 ▶ 여러 번, 검색 (끝나면 "스크롤"로 되돌린다) | first rows ≤ 150 ms. page ≤ 40 ms (21쪽부터는 ≤ 80 ms). 검색 뒤 `reload` ≤ 150 ms | |
| 2-17 | 독서 노트 메모리 | 첫 화면의 PSS와 10쪽 넘긴 뒤 PSS | 늘어난 양 ≤ 2 MB | |
| 2-18 | 리더에서 나갈 때 자동 백업 | 책을 최대한 많이 넣는다(목표 1,000권). 리더에서 PSS를 재고, 홈으로 나가 `auto backup: WROTE` 또는 `UNCHANGED`가 나오고 10초 뒤 PSS. `NOT_DUE`면 15-6처럼 시계를 이틀 뒤로 돌린다 | 시작 전 PSS + 2 MB 이내. 백업이 도는 중에 리더로 돌아오면 `auto backup: BUSY` | |
| 2-19 | 휴대폰 SMOOTH | 9-1 | 9-1 | |

- 2-16의 10,000개 기준과 counts ≤ 15 ms, drawer ≤ 5 ms는 디버그 APK(`DEBUG_SEED_NOTES`)에서만 잴 수 있다. CI는 릴리스만 만들기
  때문에, 디버그 APK가 없으면 실제 노트로 잰 값만 적는다.
- 기기가 필요 없는 항목(엔진 `TypesetterPerfTest`, 상태 줄 할당 0 `StatusModelTest`, APK 크기)은 CI·JVM 결과로 판정한다.

## 4. 가장 빠른 새로고침 모드에서 보이는지 (UI D2, NOTES §8)

기기의 앱별 e-ink 설정에서 리더플러스를 가장 빠른 모드로 바꾼다. 또는 설정 › e-ink 새로고침 › 화면 모드 묶음의 화면 모드에서
"빠르게 (FAST)"를 고른다. 앱 쪽 설정은 같은 화면의 고급 › 진단 "e-ink 제어:" 줄에 기기 이름이 보일 때만 적용된다(없으면 이
행이 꺼져 있고 이유가 보인다). 끝나면 원래대로 되돌린다(앱 쪽 설정은 "기기 설정 따름 (기본)"). 사진을 남긴다.

| # | 볼 것 | 합격 | 결과 |
|---|---|---|---|
| 4-1 | 진행 막대 | 선과 점이 보인다. 코멧에서 점의 아래쪽까지 잘리지 않고 다 보인다 (2026-10-04: 화면 아래 끝에서 4 dp 띄움) | |
| 4-2 | 위 슬롯(챕터 제목)과 아래 슬롯 3개(예: 쪽 번호 · 진행률 · 시계) | 글자를 읽을 수 있다 | |

```sh
adb shell dumpsys gfxinfo $P framestats > fs.txt
python3 - fs.txt <<'EOF'
import sys
hdr, ui, tot = None, [], []
for line in open(sys.argv[1]):
    f = line.strip().rstrip(',').split(',')
    if f[0] == 'Flags': hdr = f; continue
    if hdr and len(f) == len(hdr) and f[0] == '0':
        r = dict(zip(hdr, map(int, f)))
        ui.append((r['SyncQueued'] - r['HandleInputStart']) / 1e6)
        tot.append((r['FrameCompleted'] - r['IntendedVsync']) / 1e6)
p95 = lambda a: sorted(a)[max(0, int(len(a) * 0.95) - 1)] if a else 0
print(f"{len(ui)} frames, UI p95 {p95(ui):.1f} ms, total p95 {p95(tot):.1f} ms")
EOF
```
