# RC-S 본체 구현 결과 (2026-10-03)

ScrollReader의 슬롯·본문 표시·터치 명령·가상 페이지·로드 대기 처리를 구현했다.
ReaderActivity의 실제 모드 전환 및 수명주기 연결은 RC-A에서 한다. 아직 새 스크롤 UI는 활성화되지 않았다.

- 페이지 명령은 STEP/SMOOTH 모두 즉시 적용한다. SMOOTH도 손을 떼면 그 자리에서 멈춘다. 애니메이터·관성·타이머 보간이 없다.
- ScrollNavigation은 Android에서 분리했다. 준비되지 않은 구간에서는 이전 본문과 저장 위치를 유지하고,
  도착한 layout으로 명령을 이어 처리한다. 연속 입력은 순서를 유지한다. 드래그는 로드 뒤 자동 재개하지 않는다.
- 빈 strip 순회는 회당 64개로 제한하고, 후속 이벤트에서 계속한다. 실제 본문이 있는 위치만 publish한다.
- 8개 layout 슬롯과 재사용하는 화면 배열을 둔다. store마다 슬롯을 모두 다시 조회한다.
  보이는 범위를 즉시 보호하고, 로드 대상도 store 전에 보호한다. 세대 변경 동안 이전 renderer·geometry·본문을 유지한다.
- 가상 페이지는 요청 시에만 만들고 draw와 동일한 반올림 원점을 쓴다. 이동 중에는 마지막 정지 상태의 가상 페이지를 반환한다.
- 인용문은 최대 끝 위치를 기록하는 검색 트리로 찾는다. 앞에서 시작한 긴 인용문도 누락되지 않는다.
  같은 visible page의 목록을 재사용하고, 인용문이 없으면 공유 emptyList를 쓴다.
- 본문 draw는 저장한 배열만 순회한다. 새 layout/image prefetch와 기기 probe는 첫 draw 뒤에만 시작한다.
  이미지는 보이는 페이지가 바뀌거나 정지할 때 한 묶음으로 요청하여 매 프레임 재요청하지 않는다.
- 접근성은 기존 리더의 수동 페이지 명령 경로를 사용한다. 기기/스크롤 방식 변경은 다음 DOWN에서 적용한다.

검사:

- `tools/typecheck.sh`: 성공.
- `tools/unittest.sh`: **1,195개 전부 통과**.
- 새 테스트 15개: 동기적 한 화면 이동, 지연 로드 중 연속 입력, 빈 구간 200개, 취소와 정지 저장,
  무관성 UP, 모드별 release, 복원 anchor, 큐 증가·순환 10만 입력, 반올림 좌표 3천 배치,
  긴/중첩 인용 범위와 독립 필터의 비교.
- 기존 LINE/PARAGRAPH golden 및 엔진 성능 검사는 그대로 통과했다.
- Android Canvas·터치·메모리·프레임 성능은 RC-A 통합 후 CI/기기 검사 대상이다.

환경 복구 때 손상된 Android API jar를 Maven Central 원본으로 다시 받아 ZIP CRC 검사를 통과한 뒤 전체 검사를 실행했다.
